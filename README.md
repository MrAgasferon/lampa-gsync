# Lampa GSync — синхронизация Lampa / ByLampa через Google Таблицу

Lampa GSync — плагин для Lampa / ByLampa, синхронизирующий закладки, прогресс просмотра и настройки между устройствами пользователя через Google Таблицу на его собственном Google Диске.

Приложение запрашивает доступ только к файлам, которые создаёт само (scope `drive.file`), и email для отображения аккаунта в настройках.

[Политика конфиденциальности](privacy.html)

Каждый пользователь входит своим Google-аккаунтом (код на google.com/device), плагин создаёт у него на Диске таблицу «Lampa Sync» и синхронизирует через неё выбранные группы данных.

## 1. Google Cloud (один раз, только автору плагина)

Автоматизируемая часть:

```bash
PROJECT=lampa-sync-$(date +%s)
gcloud projects create $PROJECT
gcloud config set project $PROJECT
gcloud services enable drive.googleapis.com sheets.googleapis.com
```

Вручную в console.cloud.google.com → Google Auth Platform:

1. **Branding**: название приложения, email поддержки.
2. **Audience**: тип External, статус **In production** (в Testing refresh-токены живут 7 дней).
3. **Data access**: scope `.../auth/drive.file`, `openid`, `email`.
4. **Clients → Create client**: тип **TVs and Limited Input devices**.
5. `Client ID` и `Client secret` вставить в начало `gsync.js` (`CFG.CLIENT_ID`, `CFG.CLIENT_SECRET`).

## 2. Установка

Выложить `gsync.js` на любой HTTPS-хостинг (GitHub Pages, свой nginx) и добавить в Lampa:
Настройки → Расширения → Добавить плагин → URL.

## 3. Проверить на своей сборке

В консоли (`Object.keys(localStorage)`) убедиться, что ключи совпадают:
`favorite`, `file_view*`, `online_view`, `torrents_view`, `search_history`, `plugins`.
Если нет — поправить `claim` у нужной группы в `GROUPS`.

## Листы таблицы

| Лист | Что хранит |
|---|---|
| `_meta` | версия схемы, общая конфигурация (группы, исключения, режим) |
| `bookmarks` | закладки, «позже», история |
| `progress` | таймкоды |
| `views` | отметки просмотренного |
| `search` | история поиска |
| `settings_ui` / `settings_sources` / `plugin_settings` | настройки (ключ-значение) |
| `plugins` | список плагинов |
| `snapshots` | полные снимки, порезанные на фрагменты по 45 000 символов |

Строки только дописываются (append-only), актуальная версия элемента — с максимальным `updated_at`. Удаления — строки с `deleted=1`. Сжатие переписывает лист последними версиями и убирает tombstones старше 30 дней.

## Какие настройки общие, а какие — для устройства

| Общие для всех устройств (лист `_meta`) | Для этого устройства |
|---|---|
| Элементы синхронизации (группы) | Режим: когда синхронизировать, направление, прогресс на паузе, перезапуск |
| Исключения (список) | Уступать другим синхронизациям |
| Хранить снимков | Имя устройства |
| Ключ синхронизации — включение защиты* | Отклонённые плагины |
| | Ключ синхронизации — сам ключ* |

\* Защита ключом включается для всех устройств сразу (в таблице хранится проверочное значение), а сам ключ вводится и хранится на каждом устройстве.

В меню плагина общие пункты помечены «общее для всех устройств», локальные — «для этого устройства». Исключение (✗) означает, что значение настройки не покидает устройство; сам список исключений общий.

## Поведение

- **Первая синхронизация** устройства или группы (новое устройство, повторный вход, повторное включение группы): при конфликте побеждает таблица, включая удаления. Локальные элементы, которых нет в таблице, добавляются.
- **Конфликты** решаются по времени правки (журнал изменений ключей), а не по времени синхронизации. Часы устройства корректируются по серверу Google, если расходятся больше чем на 5 минут.
- **Закладки, прогресс просмотра и список плагинов** Lampa держит в памяти, поэтому изменения с других устройств применяются только при запуске приложения (в веб-версии — при обновлении страницы) и сразу с перезапуском. В фоне они откладываются до следующего запуска.
- **Плагины с других устройств** предлагаются списком с галочками (по умолчанию всё отмечено). Неотмеченные больше не предлагаются на этом устройстве и не удаляются у других. Сброс: Расширенные → Отклонённые плагины.
- **Дубли плагинов**: ссылки сравниваются без схемы (`http`/`https`), слэша на конце, `#…`, параметров кэша (`v`, `ver`, `version`, `_`, `t`, `nocache`, `cache`) и регистра домена. Плагин, который уже стоит под чуть другой ссылкой, не предлагается и не добавляется повторно. Дубли, созданные другой синхронизацией, GSync не чистит.
- **Группы** включаются и выключаются в Lampa GSync → Элементы синхронизации.
- **Другие синхронизации** (переключатель «Уступать другим синхронизациям», для каждого устройства): GSync пропускает данные, которые на этом устройстве уже синхронизирует другая система.
  - CUB — при входе в аккаунт: закладки и прогресс.
  - ByLampa / Lampac («Аккаунт → Синхронизация данных» на сервере ByLampa) — по признакам, которые ставят плагины синхронизации Lampac: `sync.js` (`window.sync_init`) — закладки, прогресс, отметки просмотренного; `bookmark.js` (`window.lampacBookmarkSyncInitialized`) — закладки; `timecode.js` (`window.lampac_timecode_plugin`) — прогресс. Облегчённый `sync_lite.js` не распознаётся.
- **Надёжность**: тень (последнее подтверждённое таблицей состояние) фиксируется только после успешной записи — упавшая отправка повторяется целиком, включая удаления.
- **Сжатие** выполняет одно устройство (блокировка в `_meta!D2:E2`); лист перезаписывается поверх, без промежуточного пустого состояния. Горизонт очистки удалений пишется в `_meta!D3:E…`, поэтому устройство, бывшее офлайн дольше 30 дней, не воскрешает удалённое.
- **Дубликаты таблицы** (одновременный первый вход, таблица в корзине): основной считается самая старая, дубликаты сливаются в неё и отправляются в корзину.
- **Исключения**: ✗ — ключ остаётся только на этом устройстве. Пометка ключа локальным не удаляет его на других устройствах.
- **Восстановление снимка** перезаписывает локальные ключи (со снимка другого устройства — кроме исключений) и отправляет восстановленное в таблицу. Элементы, добавленные после снимка, не удаляются.
- **Снимки**: Действия → Удалить снимки — список по дате (новые сверху) с размером, отмечаете ненужные и удаляете. «Хранить снимков» (все / последний / 3 / 5 / 10) — старые сверх лимита удаляются автоматически при сохранении нового.
- **Обратный переход на CUB или ByLampa**: включить их синхронизацию на устройствах — при включённом «Уступать другим синхронизациям» GSync сам перестанет трогать их данные. Полностью отказаться от GSync: удалить плагин или поставить «Когда синхронизировать → Вручную» на каждом устройстве.

## Перезапись таблицы с устройства

Действия → **Перезаписать таблицу с этого устройства**. Таблица очищается и заполняется данными этого устройства.

| Режим | Остальные устройства |
|---|---|
| **Эталон** | Становятся как это устройство: лишние закладки, таймкоды и синхронизируемые настройки на них удаляются (настройки — к значениям по умолчанию) |
| **Слияние** | При конфликтах побеждает это устройство, но то, чего на нём нет, остальные вернут в таблицу |

- Очищаются только листы групп, которые это устройство само заполнит заново. Группы, пропущенные из-за CUB или отсутствия ключа, не трогаются (в журнале: «не тронуты: …»).
- Привязанное к устройству (плеер, TorrServer, размер интерфейса) и снимки не трогаются.
- На остальных устройствах закладки, таймкоды и плагины применятся при следующем запуске (в веб-версии — F5). Удаление плагинов — через диалог с галочками.

## Переход с другой синхронизации (ByLampa, CUB)

Две синхронизации одних и тех же данных перетирают друг друга: подтянутое одной система принимает за правку на устройстве и разносит дальше, удалённое одной другая возвращает. Поэтому одновременно должна работать только одна.

1. На устройстве со «старой» синхронизацией дождаться, пока она подтянет свежие данные.
2. Lampa GSync → Действия → **Перезаписать таблицу с этого устройства → Эталон** — до первой обычной синхронизации этого устройства (иначе при первой синхронизации победит таблица).
3. Действия → **Сохранить снимок** — страховка.
4. Сразу выключить старую синхронизацию на всех устройствах.
5. Проверить, что закладки и таймкоды на месте. Если при выключении старая синхронизация очистила локальные данные — Действия → **Восстановить из снимка**: восстановленное уйдёт в таблицу как более свежая правка и вернётся на остальные устройства.
6. Остальные устройства перезапустить.

Вместо отключения можно оставить переключатель «Уступать другим синхронизациям»: тогда эти данные на устройстве синхронизирует CUB или ByLampa, а GSync их пропускает. Остальное (настройки, плагины, снимки) продолжает идти через GSync.

## Ключ синхронизации (защита списка плагинов)

Защищает от подмены плагинов, если кто-то получит доступ к таблице (например, через фишинг с кодом google.com/device): чужой плагин не будет предложен ни на одном устройстве.

1. На первом устройстве: Lampa GSync → Безопасность → Ключ синхронизации → **Создать ключ**. Запишите показанный ключ (16 символов вида `K7QM-3XTP-AB12-CD34`).
2. На остальных устройствах: то же меню → **Ввести ключ**. Регистр, пробелы и дефисы не важны.

Как работает:
- Каждая строка листа `plugins` подписывается HMAC-SHA256 ключом, производным от ключа синхронизации (PBKDF2, 20 000 итераций). Подпись — колонка `sig`.
- Устройство с ключом принимает только строки с верной подписью. Строки с неверной подписью игнорируются с предупреждением, без подписи — молча (запись в журнале).
- Если в таблице заведён ключ, устройство без ключа или с другим ключом не синхронизирует плагины совсем, остальные группы работают.
- Ключ хранится только на устройствах (`gsync_key`, `gsync_key_phrase`), в таблице лежит лишь проверочное значение (`_meta!D…:E…`, `key_check`) — по нему ключ не восстановить.
- Плагины, добавленные на устройстве без ключа до включения защиты, появятся на остальных после того, как это устройство получит ключ.

Не защищает: от вредоносного плагина, уже установленного на устройстве (он работает в том же origin и видит и ключ, и токены), и от подмены настроек (они не исполняют код).

Если подозреваете доступ к таблице: myaccount.google.com/permissions → Lampa Sync → удалить доступ (отзывает все токены), затем войти заново.

## Ручная правка таблицы

- Не удаляйте строки руками: элемент откатится к предыдущей версии или будет отправлен заново. Чтобы удалить, добавьте строку с тем же `item_id`/`key`, `deleted=1` и большим `updated_at`.
- Не меняйте порядок и состав колонок. Сортировать лист можно.

## Известные ограничения

- Код использует `async/await` и `fetch` (Chromium 60+). Для старых ТВ — прогнать через Babel.
- Разбиение настроек на интерфейс / источники / плагины — по префиксам ключей, может быть неточным.
- Значения больше 45 000 символов не синхронизируются (запись в журнале).
- Объекты в массивах без `url` получают ID по содержимому: одновременная правка одного такого элемента на двух устройствах даст две копии.
- Веб-версия Lampa, открытая в двух вкладках, синхронизирует из обеих — не рекомендуется.
- Фильтр секретов ловит только ключи со словами `token`, `password`, `secret`. Ключи сторонних плагинов (API-ключи, ключи аккаунтов вроде `jackett_key`, `bwa_kitkey`) синхронизируются и лежат в таблице. Чтобы не выпускать их с устройства — отметить в Исключениях (тогда на каждом устройстве их придётся задать вручную).
- Схема таблицы 2 (с версии 0.3.0, колонка `sig` в `plugins`): устройства на более старой версии плагина перестают писать в таблицу и просят обновиться.
